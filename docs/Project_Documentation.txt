PART 0 — READ THIS FIRST (Executive Summary)
What this project IS
A fully external, read-only PUBG cheat with a manually-mapped kernel driver that bypasses BattlEye's user-mode protection. It does not inject into TslGame.exe. It does not write to game memory. It reads memory through a kernel driver that is loaded via BYOVD (Bring Your Own Vulnerable Driver), and it renders its ESP/menu/radar through a transparent DirectX 11 overlay on top of the game window.

What it does at a glance
Layer	Technology	Purpose
Process	PubgExt.exe (win32 desktop app)	Loader UI + menu + ESP renderer
Transport	KEVENT shared-memory protocol (v5)	User-mode ↔ kernel RPC
Kernel driver	Manually-mapped .sys via kdmapper + iqvw64e (BYOVD)	Arbitrary read of game memory, hiding from AC
Renderer	Dear ImGui v1.90 WIP + D3D11 + DirectComposition	Transparent click-through overlay
Memory thread	144 Hz worker thread	Reads game state (players, loot, vehicles, camera)
Render thread	Overlay loop (~60 Hz, v-sync)	Draws ESP/HUD/radar from snapshot
What it does NOT do
❌ Doesn't inject into PUBG

❌ Doesn't write game memory (only reads — except a mouse-injection path through kernel)

❌ Doesn't use WriteProcessMemory / ReadProcessMemory (both are AC-flagged)

❌ Doesn't leave a permanent service in the registry (BYOVD is fully removed after load)

The 3 defining architectural decisions (and why)
KEVENT transport instead of IOCTL

A driver exposing \Device\Name + \DosDevices\Name is the first thing BattlEye's kernel module enumerates. The KEVENT protocol creates nothing in the object namespace: the only rendezvous is a shared section + 2 unnamed events, and the channel is delivered by patching the driver's own bytes before mapping.

Consequence: no IRP_MJ_* handlers, no IoCreateDevice, no symbolic link → invisible to !object and NtQueryDirectoryObject.

MmAllocateIndependentPagesEx instead of ExAllocatePoolWithTag

Pool allocations carry a tag (kdmP was the kdmapper default — a known IoC). Independent pages are section-backed, untagged, and can be per-section permissioned (RX text, RW data), which mirrors a legitimate loaded image.

"Full KEVENT" — no IOCTL backend anymore

The driver_interface_v3.cpp IOCTL path is retired. Both the ESP memory read path and the aimbot's mouse injection go through the KEVENT driver. This means only one driver exists at runtime, not two.

1.2 Why this architecture (technique rationale)
Decision	Alternative	Why chosen
External (no injection)	DLL injection into TslGame	BattlEye scans all loaded modules — injection = instant ban
Kernel driver for reads	ReadProcessMemory	Both ReadProcessMemory and NtReadVirtualMemory are hooked by BattlEye
BYOVD via iqvw64e	Unsigned kernel driver	Windows blocks unsigned drivers; BYOVD bypasses by using Intel's signed driver
MmAllocateIndependentPagesEx	ExAllocatePool	Pool = tagged & visible in !pool; independent = section-backed, indistinguishable from ntoskrnl
No IOCTL	\Device\Name + IRP	Device objects enumerable by NtQueryDirectoryObject — huge red flag
KEVENT via shared section	Named section	Named sections live in \BaseNamedObjects — enumerable
PassAllocationPtr=true	DriverObject as param1	Driver needs its own base for self-unmap (no unload in manual-mapped driver)
Work item (not thread)	PsCreateSystemThread	ETHREAD->StartAddress would point to our unmapped image — instant detection
kbdclass keyread	WH_KEYBOARD_LL	Hook chain visible; kbdclass is native

3.4 Batch mechanics
text
User: Engine wants 128 reads this tick.
  ↓
DriverInterfaceKEvent::BatchReadMemory:
  for (off = 0; off < count; off += 64):
    fill up to 64 KMP_OP_READ into Req.Ops[]
    Rodar() → SetEvent → WaitForSingleObject(Rsp, 2000ms) → verify AckSeq
    copy results to caller buffer
  ↓
The kernel driver sees 2 batches (not 1) — internal batching (see km_ipc_driver.c):
  KmpProcessBatch:
    batchProc = NULL; batchPid = 0;
    for each op:
      if (op->Pid != batchPid) { if (batchProc) ObDereferenceObject(batchProc); PsLookupProcessByProcessId(...) }
      MmCopyVirtualMemory(batchProc, addr, PsGetCurrentProcess(), Data+cursor, size)
    if (batchProc) ObDereferenceObject(batchProc)  // once per batch
  ↓
Net effect: N reads cost 1 PsLookupProcess + N MmCopyVirtualMemory (not N PsLookupProcess)

text
1. If calibrating → return (calibration takes priority)

MoveMouseTowards — 9 steps:

Cadence (every 16th packet → 4ms gap, others 2ms) — no periodic pattern

Deadzone at 1px → stop micro-corrections

Smoothing: clampedSmooth = clamp(Smooth/10, 0.01, 1) + ramp-up (first 300ms 2x faster) + firing mode 20% faster → curve = 1 - smooth^2, clamp [0.05, 0.45]

Max step: 60px (dist <80) / 30px, × aggression × randMult(1.0–1.5), cap 48px absolute

dist <8 → maxStep = dist * 0.5 + 0.5 (proportional approach)

Jitter: ±0.15px random

DriverScale: × 0.10–0.50

Fractional accumulator + round

Anti-snap: |move - lastMove| ≤ MaxDelta — allows decel, limits accel

Vertical unlock: zero moveY + remainderY (if AimbotUnlockVertical)

Final injection: TargetProcess.driver.InjectMouseMove(moveX, moveY)

RecoilControl — RCS:

text
1. Calibration (priority)
2. Configs.Aimbot.RCS check
3. Pawn validation (>= 0x1000000)
4. Weapon chain: WeaponProcessor → CurrentWeaponIndex → EquippedWeapons[i]
5. Read accumulators: RecoilValueVector (Vector2), VerticalRecovery (float)
   └─ Sanity: |rvv.x| > 100 || |rvv.y| > 100 || |vr| > 100 → discard
6. If not firing AND fully recovered → drain owed, reset
7. On first frame: anchor s_ffRvvY/s_ffVr/s_ffRvvX, skip 1 frame
8. Compute deltas: dropY = max(0, prev_y - cur_y), dropR, dropX
   └─ ONLY DECREASE counts (increase = new shot that hasn't reached camera)
9. Convert to degrees: degY = kInputPitchScale * (dropY - dropR)
   degX = kInputPitchScale * dropX
10. FOV clamp: if fov <1 || >170 → 90
    └─ degPerCount = RCSDegPerCount * (fov / 90)  ⚠️ FIXED: was fov<20→90 (broke 4x scope)
11. AutoCalibrate (optional): adjust mul via camera pitch drift
12. Raw counts: cy = sgn * (degY / degPerCount) * mul * (AR_RecoilValue/100)
               cx = -sgn * (degX / degPerCount) * mul * (AR_RecoilYaw/100)
13. Humanize: OU noise (~200ms correlation) + servo (1st-order filter)
14. Clamp to RCSMaxCounts
15. Fractional accumulator → InjectMouseMove(ix, iy)
RCS humanize — the anti-detection math:

Problem with old jitter: White noise ±18%, mean 0, resampled each frame → disappears when averaged over 100–300ms window

Fix: Ornstein-Uhlenbeck process (correlation ~200ms)

Servo: Step(owed, dt, lagS, cap): alpha = dt / (lag + dt), step = owed * alpha, owed -= step

Cap applied before debit — clipped portion stays owed

6.2 kdmapper::MapDriver() — the actual mapping
Step-by-step:

cpp
1. GetNtHeaders(data)  // validate MZ + PE\0\0 + MAGIC64
2. image_size = SizeOfImage
3. VirtualAlloc local copy (PAGE_READWRITE)  // staging in user mode
4. image_size -= (destroyHeader ? TotalVirtualHeaderSize : 0)  // = IMAGE_FIRST_SECTION VA
5. kernel_image_base =
   if AllocateIndependentPages:
     MmAllocateIndependentPagesEx(size, -1, 0, 0)
   else:
     AllocatePool(NonPagedPool, size)  // tag 'BwtE' (not 'kdmP' — known IoC)
6. Copy headers + each section into local_image
7. realBase = kernel_image_base

    └─ If not found, fallback to ntoskrnl.exe (many re-exports)

13. If AllocateIndependentPages:
    for each section:
      prot = EXECUTE+WRITE → PAGE_EXECUTE_READWRITE
           | EXECUTE only  → PAGE_EXECUTE_READ

The NtAddAtom hijack (why it works):

cpp
// x64 kernel has NX on pages. Can't write to .text directly.
// But WriteToReadOnlyMemory uses physical mapping:
//   1. GetPhysicalAddress(addr)  // IOCTL 0x25
//   2. MapIoSpace(physical, size)  // IOCTL 0x19 → writable mapping
//   3. WriteMemory(mapped, buffer, size)
//   4. UnmapIoSpace(mapped)  // IOCTL 0x1A
// The page protection on the original virtual address is bypassed — we're
// writing to a NEW writable mapping of the SAME physical page.

// This trick is used to patch NtAddAtom, and the call goes:
//   user-mode NtAddAtom (syscall)
//     → kernel NtAddAtom (patched: mov rax, target; jmp rax)
//     → target(...)
//     → returns to kernel NtAddAtom caller (syscall return)
// Then restore.

// Safety check before patch:
if (ntoskrnl!NtAddAtom[0..11] == kernel_injected_jmp) {
    kdmLog("The code was already hooked!! another instance of kdmapper running?!\n");
    return false;
}

7.1 LIT() — compile-time string obfuscation
How it works:

Every literal is XOR-encrypted at compile time

Key derived from __TIME__ (per-build) via FNV-1a 64-bit

8-byte blocks encrypted individually, aligned

SSE _mm_xor_si128 at runtime (AVX path disabled — #define JM_LITDISABLE_AVX_INTRINSICS inside crypt() kills it)

LITVOLATILE (GCC/Clang) puts constants in .text, not .rdata

_copy() uses initializer_list trick to force left-to-right evaluation order

PART 10 — ESP Layout (the "Preview Never Lies" design)
Why EspLayout.h exists: The menu's drag-preview shows where each element will land. If preview computed positions itself, it and the ESP would diverge — first bug fixes ESP, preview now lies.

Resolver(b, anchor, dx, dy, w, h, st, keepCenter) — the shared core:

cpp
constexpr float kGap = 2.0f;     // between two elements on SAME anchor
constexpr float kFolga = 5.0f;   // from box to first element

// b: Caixa { cx, top, bottom, halfW }
// st: Pilha { usado[ESP_ANC_COUNT] } — per-actor stack (NOT static!)

if anchor == ESP_ANC_TOP:
    x = b.cx
    y = b.top - kFolga - h - st.usado[anchor]
    keepCenter = true
if anchor == ESP_ANC_BOTTOM:
    x = b.cx
    y = b.bottom + kFolga + st.usado[anchor]
    keepCenter = true
if anchor == ESP_ANC_LEFT:
    x = b.cx - b.halfW - kFolga - w
    y = midY - h*0.5 + st.usado[anchor]
    keepCenter = false
if anchor == ESP_ANC_RIGHT:
    x = b.cx + b.halfW + kFolga
    y = midY - h*0.5 + st.usado[anchor]
    keepCenter = false
// + 4 corner anchors (keepCenter = false)

st.usado[anchor] += h + kGap  // ALWAYS — even on invalid anchor
return Vec2(x + dx, y + dy)
Pilha must be per-actor (NOT static): Two enemies on screen have different boxes → different stacks. Static = second enemy inherits first's accumulated height → text slides down.

Snap-to-nearest (AncoraMaisProxima): Table of 8 nominal points (no stacking, no dx/dy), squared distance loop → return closest. Used when dragging chips in menu.

16.2 Common mistakes to avoid
LIT() returns pointer to temporary. Must consume in same expression, or copy to std::string immediately. Array of LIT() pointers = dangling.

SharedData is not thread-safe by itself. Always GDataMutex.lock() → copy → unlock. Never hold lock while drawing.

Gui.Window.Size is set by render thread. Memory thread reads it → can be 0. Fall back to GetSystemMetrics.

ESP is drawn on GetBackgroundDrawList(). Widgets use GetWindowDrawList(). Don't mix.

DrawSanity::TelaOk before any Gui.* call. A NaN crashes at CircleSegmentCounts[INT_MIN] deep in ImGui.

WM_NCHITTEST/HTTRANSPARENT doesn't work cross-process. Only WS_EX_LAYERED | WS_EX_TRANSPARENT does.

DXGI_STATUS_OCCLUDED is a positive HRESULT. FAILED(hr) is false. Must compare ==.

Present(1,0) measures ~1/refresh regardless of backend. Don't use it to compare perf.

PushFont and PopFont must be in the same frame. NewFrame() resets the stack.

CheatFunction::LastExecution is int. GetTickCount64 truncates after 24.8 days.

16.3 Debugging checklist when something breaks
logs.txt location — %LOCALAPPDATA%\RenderCache\logs.txt

Find last [+] — where was the last success?

Find first [-] after it — where did it fail?

If no log lines at all — logging init failed (see BaseLog fallback chain: %LOCALAPPDATA%\RenderCache → %TEMP% → %LOCALAPPDATA% → EXE dir → logs.txt)

If crash 0xC0000005 — check [DRAW] NaN rejeitado — if absent, DrawSanity missed a call path

If driver not mapped — check [kdm] lines

If KEVENT no response — check [kmb] rodar: TIMEOUT count, Hdr.Ativo

If ESP shows but aimbot doesn't fire — check [AIM] FUNIL counters (which one is stuck?)
